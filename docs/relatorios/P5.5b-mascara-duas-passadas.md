## 3. O que mudou (`arquivo:linha`)

- `src/core/governance/secret-guard.ts:392-401`:
  - `maskPlainForJev(text, found)` deixou de invocar `collectJevSecretValues(text, found)`; agora realiza apenas a substituição dos valores presentes em `found` (ordenados do maior para o menor comprimento) pelo seu respectivo `describeSecretShape(valor)`.
- `src/core/governance/secret-guard.ts:406-465`:
  - Em `maskSecretsForJev(text)`:
    - Para JSON (objeto ou array):
      - **Passada 1 (`collectStrings`)**: percorre recursivamente todos os nós string acumulando segredos no conjunto `found` com `collectJevSecretValues`. Se `found.size === 0`, devolve imediatamente `{ text, count: 0 }` (texto original intacto).
      - **Passada 2 (`maskNode`)**: percorre novamente a estrutura substituindo todas as ocorrências de cada segredo em `found` via `maskPlainForJev(node, found)`. Retorna `{ text: JSON.stringify(result), count: found.size }`.
    - Para textos normais (não JSON ou erro no parse):
      - Chama `collectJevSecretValues(text, found)`. Se vazio, devolve `{ text, count: 0 }`; caso contrário, devolve `{ text: maskPlainForJev(text, found), count: found.size }`.
- `tests/decision/jev-mascara-duas-passadas.test.ts:1-62`:
  - Criado teste novo validando:
    (a) Segredo solto no 1º campo e atribuído no 2º campo → mascarado em ambos, `count: 1`;
    (b) Caso com a ordem dos campos invertida → mascarado em ambos;
    (c) Segredo no 1º campo e 2º campo limpo → 2º campo inalterado.
